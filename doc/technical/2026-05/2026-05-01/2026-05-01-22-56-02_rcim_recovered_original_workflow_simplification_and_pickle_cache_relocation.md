# RCIM Recovered Original Workflow Simplification And Pickle Cache Relocation

## Overview

This change will refactor the repository-owned RCIM recovered workflow under
`scripts/paper_reimplementation/rcim_ml_compensation/recovered_original_workflow/`
to reduce repeated code, translate repository-owned Italian identifiers into
English, and relocate the `.pickle` cache generated by dataframe/evaluation
loading away from `output/validation_checks/.../instances_V3/`.

The workflow is already runnable, but the current shape still mirrors too much
of the recovered original layout:

- several entrypoints repeat the same path/runtime preparation blocks;
- utility modules still expose Italian function and variable names in the
  repository-owned surface;
- validation smoke runs create large per-run pickle caches under
  `output/validation_checks/...`, which is not the desired repository
  location;
- the legacy cache name `instances_V3` is still visible in runtime paths and
  helper internals.

The goal is to simplify the active repository-owned workflow while preserving
the original numerical behavior.

## Technical Approach

The refactor will stay inside the repository-owned recovered workflow copy and
will not mutate the archived reference assets under `reference/`.

Planned implementation themes:

1. Extract repeated path/runtime/setup blocks into dedicated helper functions.
2. Translate repository-owned Italian identifiers to English where feasible
   without changing public workflow semantics.
3. Move the persistent pickle cache contract under `data/` using a new
   repository-owned cache directory name instead of `instances_V3`.
4. Keep runtime-local folders only for artifacts that are truly per-run, while
   sharing the long-lived pickle cache from `data/`.
5. Update workflow documentation so the new cache contract and the simplified
   code structure are explicit.

Expected helper consolidation areas:

- runtime dataframe copying and output-folder preparation in
  `training_models.py`;
- repeated stage bootstrap logic across `create_dataframe.py`,
  `training_models.py`, and `evaluate_models.py`;
- cache-path creation and pickle read/write handling in `utilities/statistics.py`;
- repeated prediction/export blocks inside `utilities/predictorML.py`, where
  safe helper extraction can reduce duplication without changing numerical
  behavior.

Expected naming cleanup areas:

- Italian helper names such as `genera_numeri_uniformi_interi`;
- Italian local names in `statistics.py`, `predictorML.py`, and any other
  repository-owned active script in the workflow subtree;
- legacy cache labels that still expose `instances_V3` in the active
  repository-owned surface.

## Implementation Steps

1. Audit the active recovered workflow subtree for repeated runtime/setup
   blocks, Italian identifiers, and hardcoded `instances_V3` cache handling.
2. Introduce repository-owned helper functions for repeated path/runtime
   preparation where that reduces duplication without obscuring control flow.
3. Translate repository-owned Italian identifiers to English in the active
   workflow surface, preserving behavior and avoiding changes to the archived
   reference copy.
4. Replace the per-run `instances_V3` pickle cache contract with a shared
   `data/` cache directory using a new repository-owned name, then thread that
   path through dataframe creation and evaluation.
5. Update workflow documentation to record the simplification and the cache
   relocation from validation artifacts to `data/`.
6. Run validation:
   - `py_compile` on the touched Python scope;
   - smoke runs for dataframe creation, training, and evaluation as needed;
   - touched-scope Markdown QA;
   - Sphinx rebuild only if portal-facing docs are touched.
