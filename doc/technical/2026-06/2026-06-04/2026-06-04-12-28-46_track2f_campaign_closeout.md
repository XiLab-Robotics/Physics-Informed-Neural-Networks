# Track 2F Campaign Closeout

## Overview

This technical document plans the closeout of the completed `Track 2F`
offset-aware probe campaign after the operator-launched local execution
finished all three sequential residual-offset runs.

The closeout must treat the terminal `conda run` message as a wrapper anomaly
unless a real training failure is found in the generated artifacts. The
campaign execution report currently shows `3` completed runs, `0` failed runs,
and per-run process return code `0`.

The closeout must also preserve the project direction policy: `Track 2F` does
not produce one exclusive best model. It produces three parallel best surfaces
that must remain visible and traceable:

| Surface | Required Best Role | Current Completed Run |
| --- | --- | --- |
| `global` | best bidirectional/general model candidate | `te_sequential_residual_offset_probe_remote_global` |
| `Fw` | best forward-only model candidate | `te_sequential_residual_offset_probe_remote_fw` |
| `Bw` | best backward-only model candidate | `te_sequential_residual_offset_probe_remote_bw` |

Scalar campaign ranking may still be reported for diagnostics, but it must not
collapse the three directional branches into a single deployment decision.

## Technical Approach

The closeout will inspect the generated campaign package, summarize the three
completed runs, and create the mandatory final campaign-results Markdown and
PDF deliverables. The report must explicitly separate:

- the scalar leaderboard order generated by the campaign runner;
- the `global`, `Fw`, and `Bw` branch winners;
- the unresolved need for official `Track 2` curve-first verification before
  any candidate is promoted as a compensation model.

The active campaign state will then be updated from prepared/executed state to
completed state or cleared according to the repository's current closeout
pattern. The campaign outputs, family registries, program registry, and
`Training Results Master Summary.md` will be checked for consistency.

No heavy `Track 2` offline verification matrix will be executed during this
normal closeout. It remains a separate operator-approved step after the
campaign-results report and PDF are complete.

## Implementation Steps

1. Inspect the campaign execution report, leaderboard, best-run files, per-run
   metric summaries, and terminal logs.
2. Confirm that the `conda run` terminal message did not correspond to a failed
   training run.
3. Generate a final campaign-results Markdown report under
   `doc/reports/campaign_results/` with a clear three-branch result table for
   `global`, `Fw`, and `Bw`.
4. Export and validate the styled PDF companion for the final report.
5. Check and, if needed, correct campaign result registries and the training
   master summary so the three directional branches are not collapsed into one
   single best model.
6. Update the active campaign state to reflect closeout completion.
7. Run Markdown QA on touched authored Markdown files and PDF validation on the
   exported report.
8. Report the closeout result and propose the optional `Track 2` curve-first
   verification refresh as the next separate step.
