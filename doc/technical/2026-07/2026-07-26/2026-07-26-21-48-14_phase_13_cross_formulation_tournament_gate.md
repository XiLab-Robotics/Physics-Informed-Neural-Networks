# Phase 13 Cross-Formulation Tournament Gate

## Overview

Phase 13 constructs the authoritative tournament-entry roster across the
isolated Wave 5.2 formulations. It prevents a cross-formulation campaign from
being run when no candidate has passed the physical, curve-first,
identifiability, causality, and deployment entry gates. The document is
automatically approved under the user's active sixteen-phase authorization.

## Technical Approach

Use the Phase 1 through Phase 12 reports as immutable evidence. Represent every
mechanism family in one roster, preserve its exact empirical, rejected,
offline, synthetic, deferred, or blocked state, and count candidates that are
both isolated and full-PINN eligible. If that count is zero, close the phase as
a documented no-contest result rather than manufacturing a ranking from
incommensurate or rejected formulations.

## Involved Components

- Phase 0 contract and Phase 1 through Phase 12 decision reports.
- Generic physics-portfolio feasibility builder and validator.
- Phase 13 configuration, CSV/YAML roster artifacts, analytical report,
  roadmap, backlog, ledger, usage guide, and master summaries.

## Implementation Steps

1. Verify the complete phase-evidence chain.
2. Inventory tournament entry requirements and candidate-family decisions.
3. Classify every formulation family under the common feasibility taxonomy.
4. Generate and validate the Phase 13 roster and no-contest decision.
5. Synchronize canonical documentation and advance to Phase 14 integration
   only with the roster state preserved.
6. Run touched-scope Markdown QA, final-newline checks, Sphinx, diff checks,
   staged-size checks, and create the dedicated Phase 13 commit.
